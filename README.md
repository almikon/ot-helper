# ОхранаПро — MVP

Работающий статический прототип сервиса охраны труда: **рабочий кабинет + интерактивный помощник по СОУТ**.

## Возможности

- `index.html` — главная страница с обзором, задачами, рабочими местами и реестром названий документов.
- `assistant.html` — пошаговый опрос СОУТ на основе исходной диаграммы. Результат предлагает предварительные действия, которые можно добавить в задачи кабинета.
- Хранение всех данных локально в `localStorage` браузера. Сервер, сборка и зависимости не нужны.

## Локальный запуск

Откройте `index.html` в браузере или запустите локальный сервер:

```bash
python3 -m http.server 8000
```

Затем перейдите на `http://localhost:8000`.

## Публикация на GitHub Pages

1. Создайте на GitHub новый репозиторий `ohranapro-mvp` (публичный, если ссылка должна быть доступна всем).
2. Загрузите **содержимое** этой папки в корень репозитория. Важно, чтобы `index.html` находился именно в корне.
3. Убедитесь, что основная ветка называется `main`.
4. В разделе **Settings → Pages → Build and deployment** выберите **Source: GitHub Actions**.
5. Откройте **Actions**, дождитесь успешного выполнения `Deploy to GitHub Pages`.
6. Ссылка на сайт появится в **Settings → Pages**. Обычный формат: `https://<ваш-логин>.github.io/ohranapro-mvp/`.

Для изменений достаточно коммита в `main`: workflow `.github/workflows/pages.yml` публикует сайт автоматически.

### Загрузка через git

```bash
git init
git add .
git commit -m "Initial MVP: workspace and SOUT assistant"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/ohranapro-mvp.git
git push -u origin main
```

Создайте пустой репозиторий на GitHub перед `git push` (без автогенерации README, так как он есть здесь).

## Ограничения

**Не готов к производственному использованию.** Правила СОУТ и формулировки в опросе предварительные и требуют проверки экспертом по охране труда и юристом. Данные существуют только в браузере конкретного человека: на другом устройстве/у коллег они будут другими. Не вводите персональные данные и сведения ограниченного доступа. Хостинг GitHub Pages не обеспечивает серверное хранение или разграничение доступа. Для общего рабочего процесса понадобятся авторизация, база данных и управление доступом.
